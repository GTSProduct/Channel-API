# Integration Notes

This page covers key integration requirements for the CPaaS+ WhatsApp Wrapper API, including the customer-service window, sender identification, media IDs, message IDs, and authentication.

## 24-hour customer-service window

Free-form WhatsApp messages can be sent only within 24 hours of the recipient's most recent inbound message to your business. This applies to the message types documented here, including text, media, interactive messages, locations, contacts, and reactions.

Outside this window, a message request may be rejected with a re-engagement error from Meta.

### Re-engagement workflow

If a re-engagement error occurs:

1. Send an approved template or campaign message to the recipient.
2. Have the recipient reply to your business from the same number.
3. Once the recipient replies, the 24-hour customer-service window reopens for the supported free-form message types.

Use your approved template or campaign process for the initial re-engagement message.

## Sender hash

The sender hash identifies the registered WhatsApp sender and forms part of the request URL.

Retrieve it from the **Numbers** section of the WhatsApp channel in the CPaaS+ Portal.

Example endpoint:

```http
POST /api/whatsapp/{Sender Hash}/messages
```

Replace `{Sender Hash}` with the value assigned to your registered sender.

## Recipient number format

The top-level `to` field must contain the recipient's WhatsApp number in international format, without a leading `+`.

Example:

```json
{
  "to": "919373084880"
}
```

This requirement applies to the top-level message recipient field.

## Media IDs

Audio, image, video, document, and sticker messages require a media ID returned by the Media Upload API.

Before sending one of these message types:

1. Upload the media file using the Media Upload API.
2. Capture the media ID returned by the upload operation.
3. Include the ID in the corresponding message object, such as `audio.id`, `image.id`, `video.id`, `document.id`, or `sticker.id`.

The Media Upload API's endpoint and request specification are not detailed here. Refer to the applicable media-upload documentation for those details.

## Message IDs (`wamid`)

Reaction, Contextual Reply, and Read Receipt requests use a WhatsApp message ID (`wamid`) to identify the message being referenced.

The message ID is available in the response to the original send or through your inbound webhook.

| Operation | Message ID field | Purpose |
|---|---|---|
| Reaction | `reaction.message_id` | Identifies the message being reacted to. |
| Contextual Reply | `context.message_id` | Identifies the earlier message being replied to. |
| Read Receipt | `message_id` | Identifies the inbound message being marked as read. |

**Important:** A read receipt must reference an incoming message from the recipient. An outbound message ID cannot be marked as read.

## Bearer tokens

Generate and revoke Bearer tokens through the **API** tab in the CPaaS+ Portal.

The Portal does not display a generated token again, so store it securely when it is created. Include the token in the `Authorization` header of each authenticated request.

```http
Authorization: Bearer <token>
```

## Acceptance is not delivery

A successful API response indicates that the request was accepted for processing or delivery. It does not, by itself, confirm that the recipient received the message.

Refer to [Common HTTP Status Codes](../status-codes) for the documented HTTP status codes, meanings, and possible causes.
