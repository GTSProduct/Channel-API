# Integration Notes

This page consolidates the general integration notes at the end of the source guide.

## 24-hour customer-service window

The guide states that Meta enforces a 24-hour customer-service window. Free-form messages described in the guide—including text, media, interactive, location, contacts, and reactions—can only be sent to a recipient within 24 hours of their last inbound message to you.

Outside that window, requests to the messages endpoint may be rejected with a re-engagement error from Meta.

### Re-engagement workflow described in the guide

If a re-engagement error occurs while testing the Wrapper API:

1. Send an approved template/campaign message to the recipient.
2. Have the recipient reply on the same number.
3. The 24-hour window will reopen for the message types documented in the guide.

This page preserves the workflow described by the source guide; consult your approved template/campaign process for the applicable implementation details.

## Sender hash

The sender hash in the URL path identifies the registered WhatsApp sender. Obtain it from the CPaaS+ Portal under the WhatsApp channel's **Numbers** section.

## Recipient number format

The guide says the top-level `to` field must contain the recipient's number in international format without a leading plus sign. Example: `919373084880`.

## Media IDs

Media IDs returned by the Media Upload API are required for audio, image, video, document, and sticker messages. Upload the file first, capture the returned ID, and pass it in the corresponding message object. The supplied PDF does not include the upload endpoint details.

## Message IDs (`wamid`)

The guide states that message IDs required by Reaction, Contextual Reply, and Read Receipt calls are returned in the response to the original send or received through your inbound webhook.

- **Reaction:** pass the target message ID in `reaction.message_id`.
- **Contextual reply:** pass the earlier message ID in `context.message_id`.
- **Read receipt:** pass the inbound message ID in `message_id`.

The guide specifically notes that a read receipt must reference an incoming message from the recipient; an outbound message ID cannot be marked as read.

## Bearer tokens

Bearer tokens can be generated and revoked from the CPaaS+ Portal under the API tab. The guide warns that a generated token will not be displayed again, so store it securely.

## Acceptance is not delivery

A success status indicates that the message was accepted by CPaaS+/Meta for delivery. It does not guarantee that the recipient has received it. See [Common HTTP Status Codes](../status-codes).
