# Common HTTP Status Codes

The following HTTP status codes describe common outcomes when submitting requests to the WhatsApp Wrapper API.

| HTTP code | Meaning | Possible cause |
|---|---|---|
| `200` | OK | Message accepted for delivery. This does not guarantee that the recipient received the message. |
| `400` | Bad Request | Invalid JSON, missing required fields, or malformed recipient number. |
| `401` | Unauthorized | Invalid, expired, or missing Bearer token. |
| `403` | Forbidden | Sender account is not permitted to message the recipient. A re-engagement requirement may apply. |
| `404` | Not Found | Account ID in the URL does not exist. |
| `413` | Payload Too Large | Uploaded media file exceeds Meta's size limit for its type. |
| `429` | Too Many Requests | Messaging rate limit for the sender number has been exceeded. |
| `500` | Internal Server Error | Server-side issue. Retry or contact support. |

## Accepted versus delivered

An HTTP `200 OK` response indicates that the message was accepted for delivery. It does **not** confirm that the recipient received the message.

## Troubleshooting

- **`400 Bad Request`:** Check that the request body contains valid JSON, all required fields are present, and the recipient number is correctly formatted.
- **`401 Unauthorized`:** Verify that the Bearer token is present, valid, and not expired.
- **`403 Forbidden`:** Check whether the recipient is outside the 24-hour customer-service window. If applicable, follow the re-engagement workflow in [Integration Notes](integration-notes).
- **`404 Not Found`:** Verify the account or sender identifier used in the request URL.
- **`413 Payload Too Large`:** Check the uploaded media file against Meta's size limit for that media type. Numeric size limits are not specified here.
- **`429 Too Many Requests`:** The sender number's messaging rate limit has been exceeded. A retry interval is not specified here.
- **`500 Internal Server Error`:** Retry the request or contact support. A retry schedule is not specified here.

Consult the API response and your integration logs for details specific to an individual request.
