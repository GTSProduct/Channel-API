## Overview

The CPaaS+ WhatsApp Wrapper API is a simplified REST layer built on top of Meta's WhatsApp Cloud API. It allows developers to send supported WhatsApp message types through a common CPaaS+ endpoint rather than calling Meta's Graph API directly.

The API supports text, media, interactive messages, locations, contacts, reactions, stickers, and messaging controls. Message requests use JSON, while media uploads use `multipart/form-data`. Requests are authenticated using Bearer tokens.

For details of the underlying message objects, refer to [Meta's WhatsApp Cloud API — Send Messages](https://developers.facebook.com/docs/whatsapp/cloud-api/guides/send-messages).

## Supported message types

| Message type | Description |
|---|---|
| Text | Send plain text, optionally with a link preview. |
| Audio | Send an audio clip or voice note using a media ID. |
| Image | Send an image with an optional caption. |
| Video | Send a video with an optional caption. |
| Document | Send a PDF or other document with an optional filename and caption. |
| Sticker | Send a static or animated WebP sticker using a media ID. |
| Contacts | Share one or more contact cards. |
| Location | Share a pinned location using coordinates, with an optional name and address. |
| Location request | Ask the recipient to share their current location. |
| Interactive — CTA URL | Send a message with a button that opens a URL. |
| Interactive — List | Present selectable options grouped into sections. |
| Interactive — Reply buttons | Present up to three quick-reply buttons. |
| Reaction | React to a specific message using an emoji. |
| Contextual reply | Reply to an earlier message with its context. |
| Typing indicators and read receipts | Mark an inbound message as read and optionally display a typing indicator. |

## Common endpoint

Most message types use the same HTTP method and endpoint:

```http
POST /api/whatsapp/{Sender Hash}/messages
```

The JSON request body determines the message type. The `type` field and its corresponding object, such as `text`, `image`, or `interactive`, must match the message being sent.

Refer to the individual API pages for the parameters and request examples for each message type.

## Typical request flow

1. Generate a Bearer token from the **API** tab in the CPaaS+ Portal. Store it securely because the Portal does not display the generated token again.
2. Retrieve your registered sender hash from **Numbers** in the WhatsApp channel of the CPaaS+ Portal.
3. For audio, image, video, document, and sticker messages, upload the media file first using the Media Upload API and retain the returned media ID.
4. Send a `POST` request to the messages endpoint with the required headers and JSON payload.
5. Check the HTTP response. A successful response indicates that the request was accepted for processing or delivery; it does not confirm that the recipient received the message.

## Important integration rule: 24-hour customer-service window

Free-form messages can be sent only within 24 hours of the recipient's most recent inbound message to your business. Outside this window, requests may be rejected with a re-engagement error.

To reopen the window, send an approved template or campaign message and have the recipient reply to your business. See [Integration Notes](integration-notes) for details.
