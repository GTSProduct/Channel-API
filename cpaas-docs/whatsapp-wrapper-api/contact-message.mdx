# Contact Message

Send one or more vCard-style contact cards to a WhatsApp recipient through the CPaaS+ WhatsApp Wrapper API.

A contact card can include a person's name and optional details such as phone numbers, email addresses, postal addresses, organisation information, and URLs.

## Endpoint

**Method:** `POST`

**Path:** `/api/whatsapp/{Sender Hash}/messages`

**Sandbox base URL:** `https://testqa.cpaas.globeteleservices.com`

Replace `{Sender Hash}` with the hash assigned to your registered WhatsApp sender.

## Authentication and headers

Every request requires a valid Bearer token generated in the **API** tab of the CPaaS+ Portal.

| Header | Value |
|---|---|
| `Accept` | `application/json` |
| `Content-Type` | `application/json` |
| `Authorization` | `Bearer <token>` |

## Request parameters

Submit the following fields in the JSON request body.

| Parameter | Required | Description |
|---|---|---|
| `messaging_product` | Yes | Fixed value `"whatsapp"`. |
| `to` | Yes | Recipient's WhatsApp number in international format, without a leading `+`. |
| `type` | Yes | Fixed value `"contacts"`. |
| `contacts[].name` | Yes | Name object containing `formatted_name` and the supported name fields: `first_name`, `last_name`, `middle_name`, `prefix`, and `suffix`. |
| `contacts[].phones` | Optional | Array of phone objects containing `phone` and `type`; `wa_id` may also be included. |
| `contacts[].emails` | Optional | Array of email objects containing `email` and `type`. |
| `contacts[].addresses` | Optional | Array of address objects. The documented fields include `street`, `city`, `state`, `zip`, `country`, and `type`. The example also includes `country_code`. |
| `contacts[].org` | Optional | Organisation object containing `company`, `department`, and `title`. |
| `contacts[].urls` | Optional | Array of URL objects containing `url` and `type`. |

The `[]` notation indicates an array. For example, `contacts[].phones` represents the phone details for a contact in the `contacts` array.

## Example request

Use the following JSON as the request body. Replace the example values with the contact and recipient details for your integration.

```json
{
  "messaging_product": "whatsapp",
  "to": "919373084880",
  "type": "contacts",
  "contacts": [
    {
      "name": {
        "formatted_name": "Barbara Johnson",
        "first_name": "Barbara",
        "last_name": "Johnson",
        "middle_name": "Joana",
        "prefix": "Dr.",
        "suffix": "Esq."
      },
      "phones": [
        {
          "phone": "+16505559999",
          "type": "Landline"
        },
        {
          "phone": "+19175559999",
          "type": "Mobile",
          "wa_id": "19175559999"
        }
      ],
      "emails": [
        {
          "email": "bjohnson@luckyshrub.com",
          "type": "Work"
        }
      ],
      "addresses": [
        {
          "street": "1 Lucky Shrub Way",
          "city": "Menlo Park",
          "state": "CA",
          "zip": "94025",
          "country": "United States",
          "country_code": "US",
          "type": "Office"
        }
      ],
      "org": {
        "company": "Lucky Shrub",
        "department": "Legal",
        "title": "Lead Counsel"
      },
      "urls": [
        {
          "url": "https://www.luckyshrub.com",
          "type": "Company"
        }
      ]
    }
  ]
}
```

## Responses and errors

The documentation provides a common HTTP status-code table rather than a separate response-body example for this message type.

Refer to [Common HTTP Status Codes](../status-codes) for the documented status codes, meanings, and possible causes. An HTTP success status indicates that the message was accepted for delivery; it does not by itself confirm receipt by the recipient.
