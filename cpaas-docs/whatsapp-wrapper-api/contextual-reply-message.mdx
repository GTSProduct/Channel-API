# Contextual Reply Message

Send a text message that quotes and replies to a specific earlier message in the conversation. The `context.message_id` field identifies the message being replied to.

## Endpoint

**Method:** `POST`

**Path:** `/api/whatsapp/{Sender Hash}/messages`

**Sandbox base URL:** `https://testqa.cpaas.globeteleservices.com`

Replace `{Sender Hash}` with the hash assigned to your registered WhatsApp sender.

## Authentication and headers

Every request requires a valid Bearer token generated in the **API** tab of the CPaaS+ Portal.

| Header | Value |
|---|---|
| `Accept` | `application/json` |
| `Content-Type` | `application/json` |
| `Authorization` | `Bearer <token>` |

## Request parameters

Submit the following fields in the JSON request body.

| Parameter | Required | Description |
|---|---|---|
| `messaging_product` | Yes | Fixed value `"whatsapp"`. |
| `recipient_type` | Optional | Fixed value `"individual"`; this is the default. |
| `to` | Yes | Recipient's WhatsApp number in international format, without a leading `+`. |
| `context.message_id` | Yes | The `wamid` of the earlier message being replied to. |
| `type` | Yes | Fixed value `"text"`. |
| `text.body` | Yes | Text content of the reply. |

## Example request

Use the following JSON as the request body. Replace the sender hash, token, recipient number, and message ID with values from your integration.

```bash id="5b3d9f"
curl --location 'https://testqa.cpaas.globeteleservices.com/api/whatsapp/{Sender Hash}/messages' \
--header 'Accept: application/json' \
--header 'Content-Type: application/json' \
--header 'Authorization: Bearer {{Bearer Token}}' \
--data '{
  "messaging_product": "whatsapp",
  "recipient_type": "individual",
  "to": "919373084880",
  "context": {
    "message_id": "wamid.HBgMOTE5MzczMDg0ODgwFQIAERgSN0RDMUZCMEVGRjQ3MDA2ODNDAA=="
  },
  "type": "text",
  "text": {
    "body": "You'\''re welcome!"
  }
}'
```

## Important considerations

- `context.message_id` must identify the earlier message that the reply references.
- The `wamid` required for contextual replies is returned in the response to the original send or received through an inbound webhook.
- The top-level `to` field must use international number format without a leading `+`.
- The 24-hour customer-service window applies to free-form replies. See [Integration Notes](integration-notes) for details.

## Responses and errors

The documentation provides a common HTTP status-code table rather than a separate response-body example for this message type.

Refer to [Common HTTP Status Codes](../status-codes) for the documented status codes, meanings, and possible causes. An HTTP success status indicates that the message was accepted for delivery; it does not by itself confirm receipt by the recipient.
