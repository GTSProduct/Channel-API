# Typing Indicators & Read Receipts

Mark an inbound WhatsApp message as read and optionally show a typing indicator while preparing a reply.

## Endpoint

**Method:** `POST`

**Path:** `/api/whatsapp/{Sender Hash}/messages`

**Sandbox base URL:** `https://testqa.cpaas.globeteleservices.com`

Replace `{Sender Hash}` with the hash assigned to your registered WhatsApp sender.

## Authentication and headers

Every request requires a valid Bearer token generated in the **API** tab of the CPaaS+ Portal.

| Header | Value |
|---|---|
| `Accept` | `application/json` |
| `Content-Type` | `application/json` |
| `Authorization` | `Bearer <token>` |

## Request parameters

Submit the following fields in the JSON request body.

| Parameter | Required | Description |
|---|---|---|
| `messaging_product` | Yes | Fixed value `"whatsapp"`. |
| `status` | Yes | Fixed value `"read"`. |
| `message_id` | Yes | WhatsApp message ID (`wamid`) of the inbound message to mark as read. |
| `typing_indicator.type` | Optional | Fixed value `"text"` to also display a typing indicator. |

## Example request

Use the following JSON as the request body. Replace the message ID with the ID of the inbound message you want to mark as read.

```json id="m4q8vc"
{
  "messaging_product": "whatsapp",
  "status": "read",
  "message_id": "wamid.HBgMOTE5MzczMDg0ODgwFQIAERgSNzJFNDJBOUFFNjA4MUZGNUEyAA==",
  "typing_indicator": {
    "type": "text"
  }
}
```

## Important considerations

- The `message_id` must identify an incoming message from the recipient.
- An outbound message ID cannot be marked as read.
- The optional `typing_indicator.type` field uses the fixed value `"text"` when a typing indicator is included.
