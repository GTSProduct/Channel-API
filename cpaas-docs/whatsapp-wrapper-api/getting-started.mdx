# Getting Started

Connect your application to the CPaaS+ WhatsApp Wrapper API using your API token, registered sender hash, and the appropriate message payload.

## Base URL

Use the following sandbox endpoint for testing:

```text
https://testqa.cpaas.globeteleservices.com
```

Replace the sandbox host with your production CPaaS+ host when it is issued for your account.

## Authentication

Every request must include a Bearer token in the `Authorization` header.

```http
Authorization: Bearer <token>
```

Generate the token from the **API** tab in the CPaaS+ Portal. The token is associated with a specific WhatsApp sender account.

**Token security:** Store the token securely when it is generated. The CPaaS+ Portal will not display the same token again. Tokens can be generated and revoked through the Portal.

## Identify your WhatsApp sender

The sender hash identifies your registered WhatsApp sender and forms part of the request URL. Retrieve it from the **Numbers** section of the WhatsApp channel in the CPaaS+ Portal.

The example below illustrates the sender hash format:

```text
25bd1f59-e3e8-4997-9d6f-8ff103ced889
```

Use the sender hash assigned to your own account.

## API endpoint

WhatsApp message requests use the following endpoint:

```http
POST /api/whatsapp/{Sender Hash}/messages
```

The complete sandbox URL is:

```text
https://testqa.cpaas.globeteleservices.com/api/whatsapp/{Sender Hash}/messages
```

Replace `{Sender Hash}` with your registered sender hash. The message type and its associated fields are specified in the JSON request body.

## Request headers

Include the following headers in message requests:

```http
Accept: application/json
Content-Type: application/json
Authorization: Bearer <token>
```

The API uses JSON request bodies for messaging operations. Media upload uses `multipart/form-data`.

## Recipient number format

The top-level `to` field must contain the recipient's WhatsApp number in international format, without a leading plus sign.

Example:

```json
{
  "to": "919373084880"
}
```

Phone numbers included inside a contact-card payload are separate contact details and are not the top-level message recipient.

## Media messages

Audio, image, video, document, and sticker messages reference uploaded files by media ID.

Before sending one of these message types:

1. Upload the file using the Media Upload API.
2. Capture the media ID returned by the upload operation.
3. Include the ID in the appropriate field, such as `image.id`, `audio.id`, or `document.id`.

Refer to [Media Handling](media-handling) for the media workflow and supported message fields.

## Before sending your first request

- Confirm the correct sandbox or production base URL.
- Retrieve the sender hash from the CPaaS+ Portal.
- Generate and securely store a valid Bearer token.
- Format the recipient number without a leading plus sign.
- For media messages, obtain the required media ID before sending.
- Check the [Integration Notes](integration-notes) for the 24-hour customer-service window and message ID requirements.
