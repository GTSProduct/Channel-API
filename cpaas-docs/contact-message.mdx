# Contact Message

Share one or more vCard-style contact cards. The guide describes name, phone, email, address, organisation, and URL details.

## Endpoint

```http
POST /api/whatsapp/{Sender Hash}/messages
```

**Sandbox base URL:** `https://testqa.cpaas.globeteleservices.com`

## Common headers

```http
Accept: application/json
Content-Type: application/json
Authorization: Bearer <token>
```

The Bearer token is generated in the CPaaS+ Portal under the API tab. Replace `{Sender Hash}` with the registered sender hash obtained from the WhatsApp channel's Numbers section. The guide says the top-level `to` value should use international format without a leading `+`.

## Parameters

| Parameter | Required | Description from the guide |
|---|---|---|
| `messaging_product` | Yes | Fixed value `"whatsapp"`. |
| `to` | Yes | Recipient WhatsApp number, without a leading `+`. |
| `type` | Yes | Fixed value `"contacts"`. |
| `contacts[].name` | Yes | Object with `formatted_name` plus first, last, middle name, prefix, and suffix fields. |
| `contacts[].phones` | Optional | Array of phone objects with `phone`, `type`, and optional `wa_id`. |
| `contacts[].emails` | Optional | Array of email objects with `email` and `type`. |
| `contacts[].addresses` | Optional | Array of address objects; guide lists street, city, state, zip, country, and type. Its example also includes `country_code`. |
| `contacts[].org` | Optional | Object with company, department, and title. |
| `contacts[].urls` | Optional | Array of URL objects with `url` and `type`. |

## Request example

Use the following JSON as the request body. Replace the sender hash, token, recipient, IDs, and example values with values for your integration.

```json
{
  "messaging_product": "whatsapp",
  "to": "919373084880",
  "type": "contacts",
  "contacts": [
    {
      "name": {
        "formatted_name": "Barbara Johnson",
        "first_name": "Barbara",
        "last_name": "Johnson",
        "middle_name": "Joana",
        "prefix": "Dr.",
        "suffix": "Esq."
      },
      "phones": [
        { "phone": "+16505559999", "type": "Landline" },
        { "phone": "+19175559999", "type": "Mobile", "wa_id": "19175559999" }
      ],
      "emails": [
        { "email": "bjohnson@luckyshrub.com", "type": "Work" }
      ],
      "addresses": [
        {
          "street": "1 Lucky Shrub Way",
          "city": "Menlo Park",
          "state": "CA",
          "zip": "94025",
          "country": "United States",
          "country_code": "US",
          "type": "Office"
        }
      ],
      "org": { "company": "Lucky Shrub", "department": "Legal", "title": "Lead Counsel" },
      "urls": [ { "url": "https://www.luckyshrub.com", "type": "Company" } ]
    }
  ]
}
```

## Responses and errors

The source guide provides a common HTTP status-code table rather than a separate response body for this message type. See [Common HTTP Status Codes](../status-codes) for the documented meanings and possible causes. A success status indicates acceptance for delivery and does not guarantee that the recipient received the message.
