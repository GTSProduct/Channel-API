# RCS Webhook User Guide

This guide documents the customer-facing JSON structure and values observed in the supplied GTS CPaaS RCS Status sample. It covers outbound message lifecycle notifications, delivery reports, RCS interactions, and incoming text messages.

A field may appear only for particular event types. A `null` value means the field is null in that sample; it does not establish that the field is always required for every event.

## 1. Webhook event types

| `event_type` | `status` / `rcs_event_type` | Description |
| --- | --- | --- |
| `message_dispatch` | `submit` | Message submitted for dispatch |
| `message_dispatch` | `sent` | Message sent, as represented by the callback |
| `message_delivery` | `delivered` | Message delivered to the recipient |
| `message_delivery` | `Failed` | Failure value listed in the supplied event table; no failed-delivery sample was supplied |
| `message_delivery` | `read` | Message read by the recipient |
| `rcs_event` | `ACTION` | User selected an action/CTA |
| `rcs_event` | `REPLY` | User selected a suggested reply/quick reply |
| `incoming_message` | `received` | Incoming user message received |

## 2. Top-level webhook fields

| Field | Type | Observed value / format | Definition |
| --- | --- | --- | --- |
| `event_type` | String | `message_dispatch`, `message_delivery`, `rcs_event`, `incoming_message` | Webhook event category |
| `status` | String / Null | `submit`, `sent`, `delivered`, `read`, `received` | Event status in the applicable samples |
| `rcs_event_type` | String | `ACTION`, `REPLY` | Interaction type for `rcs_event` |
| `message_id` | String / Null | UUID-like identifier or null | GTS message identifier; null in the incoming-message sample |
| `external_message_id` | String / Null | String or null | External message identifier, when available |
| `corelation_id` | String / Null | null in supplied examples | Correlation identifier; preserve this exact spelling |
| `rcs_message_id` | String / Null | null in supplied examples | RCS message reference |
| `timestamp` | String | ISO 8601 timestamp | Timestamp associated with the webhook event |
| `message` | Object | Object | Message details and event-specific content or payload |
| `agent` | Object | Object | RCS agent information |
| `additional_data` | Object | Object | Additional metadata; fields vary by callback |
| `event_data` | Object | Object | User interaction details |
| `delivery_info` | Object | Object | Delivery lifecycle and status details |

## 9. Field types and value conventions

- **String:** Text, identifiers, phone numbers, URLs, timestamps, and enumerated values are represented as JSON strings in the supplied examples.
- **Integer:** `delivery_info.attempts` is an integer.
- **Boolean:** `additional_data.provider_response.success` is a Boolean (`true` in the supplied submit sample).
- **Object:** A nested JSON object containing related fields.
- **Array of Objects:** `carousel.contents` and `suggestions` contain arrays of objects.
- **Null:** Examples include `message_id`, `corelation_id`, `rcs_message_id`, `thumbnailUrl`, delivery timestamps, and error fields.
- **Timestamp:** Timestamp strings use ISO 8601 format with a UTC `Z` suffix.
- **Phone number:** Phone numbers are strings, not numeric JSON values. The samples show values both with and without a leading `+`, depending on the field.

## 10. Notes on the supplied payload contract

1. Use JSON field names exactly as documented, including the spelling `corelation_id`.
2. The supplied samples show `message.content` in dispatch callbacks and `message.payload` in delivery callbacks and incoming text. Preserve the field name received.
3. Fields and nested objects vary by event type. Do not expect every field in every callback.
4. Provider-related metadata is documented because it appears in the supplied JSON; it is not required to process the primary event category and status.
5. The supplied sample does not include a failed-delivery callback. A failure event type, status value, and failure payload cannot be defined from the available sample.
6. This guide documents only fields and values evidenced in the supplied RCS Status sample; it does not infer additional callback fields or enum values.
