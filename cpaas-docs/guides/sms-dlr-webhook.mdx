## Overview

CPaaS+ provides a Delivery Report (DLR) Callback / Webhook mechanism that notifies your application about the delivery status of SMS messages sent through the CPaaS+ platform. Instead of polling for status, the GTS server pushes the delivery status to a webhook URL configured on your account as soon as a status update is available.

Webhooks are HTTP-based, use JSON data format, and can be set up with Bearer Token authentication.

## Configure the webhook

1. Log in to your CPaaS+ account.
2. Navigate to your profile picture at the top-right of the web portal.
3. Select **Settings**.
4. Open the **Client Webhook** tab.
5. Select **Create New Webhook**.
6. Enter a name for the webhook configuration.
7. Select **SMS Channel** from the Channel dropdown.
8. Enter your application endpoint in **Webhook URL**.
9. Under the **Subscriptions** tab, select **Default DLR** and set the status to **Active**.
10. Optionally enable **Bulk push** to receive multiple DLRs in a single webhook call.
11. Click **Submit** to save the configuration.

You can edit a configuration by clicking **Edit** against the relevant entry.

## Webhook source IP

GTS sends webhook and callback notifications, including SMS DLR callbacks, from the following static IP address. Whitelist this IP on your firewall or security group so callbacks are not blocked.

```text
3.6.167.57
```

## SMS DLR callback

Once an SMS is submitted and its delivery status is confirmed (or fails) at the operator/handset level, CPaaS+ sends an asynchronous HTTP callback to the webhook URL configured on your account with the final delivery status of the message.

### Sample payload

The following is a sample DLR callback payload:

```json
{
  "message_id": "803cbc7b-3657-4e6c-8de0-e4f37e3b0e0c",
  "service": "T",
  "sender": "XXXXX",
  "mobile": "91XXXXXXXX",
  "status": "DELIVRD",
  "code": "000",
  "submit_at": "2026-08-10 11:47:22",
  "dlr_received_at": "2026-08-10 11:47:22",
  "entity_id": "1701164872369547174",
  "template_id": "1507166245188685280",
  "units": "1",
  "correlation_id": null
}
```

### Payload field reference

The callback values are sent in the request body.

| Field | Type | Description |
| --- | --- | --- |
| `message_id` | String (UUID) | Unique message identifier generated by CPaaS+ for the submitted SMS. |
| `service` | String | Service/route type used to send the message (T = Transactional). |
| `sender` | String | Sender ID / Header used to send the SMS. |
| `mobile` | String | Destination mobile number the SMS was sent to, without the + prefix. |
| `status` | String | Current delivery status of the message, e.g. `DELIVRD`, `FAILED`, `REJECTED`, `Sent`, `Pending`. |
| `code` | String | Status/error code corresponding to the status. See the error code reference below. |
| `submit_at` | `YYYY-MM-DD HH:MM:SS` | Timestamp when the message was submitted to the operator. |
| `dlr_received_at` | `YYYY-MM-DD HH:MM:SS` | Timestamp when the delivery report was received. |
| `entity_id` | String | DLT-registered Entity ID (PEID) used for the message. |
| `template_id` | String | DLT-registered Template ID used for the message content. |
| `units` | String | Number of SMS units/segments consumed by the message. |
| `correlation_id` | String / null | Client-supplied reference ID passed at submission. |

## Callback handling notes

- Your webhook endpoint should respond with **HTTP 200 OK** promptly on receipt. A non-200 response or timeout may result in retries.
- If your application is unable to accept the DLR for specific messages, contact [cpaas.support@globeteleservices.com](mailto:cpaas.support@globeteleservices.com).
- Any new error codes introduced by operators will be mapped and pushed to the configured webhook.
