# Typing Indicators & Read Receipts

Mark an inbound message as read and optionally show a typing indicator to the recipient while a reply is being prepared.

## Endpoint

```http
POST /api/whatsapp/{Sender Hash}/messages
```

**Sandbox base URL:** `https://testqa.cpaas.globeteleservices.com`

## Common headers

```http
Accept: application/json
Content-Type: application/json
Authorization: Bearer <token>
```

The Bearer token is generated in the CPaaS+ Portal under the API tab. Replace `{Sender Hash}` with the registered sender hash obtained from the WhatsApp channel's Numbers section. The top-level `to` value should use international format without a leading `+`.

## Parameters

| Parameter | Required | Description from the guide |
|---|---|---|
| `messaging_product` | Yes | Fixed value `"whatsapp"`. |
| `status` | Yes | Fixed value `"read"`. |
| `message_id` | Yes | The `wamid` of the inbound message to mark as read. |
| `typing_indicator.type` | Optional | Fixed value `"text"` to also display a typing indicator. |

## Request example

Use the following JSON as the request body. Replace the sender hash, token, recipient, IDs, and example values with values for your integration.

```json
{
  "messaging_product": "whatsapp",
  "status": "read",
  "message_id": "wamid.HBgMOTE5MzczMDg0ODgwFQIAERgSNzJFNDJBOUFFNjA4MUZGNUEyAA==",
  "typing_indicator": { "type": "text" }
}
```

## Notes

`message_id` must belong to an incoming message from the recipient. An outbound message ID cannot be marked as read.

## Responses and errors

See [Common HTTP Status Codes](../status-codes) for the documented meanings and possible causes. A success status indicates acceptance for delivery and does not guarantee that the recipient received the message.
